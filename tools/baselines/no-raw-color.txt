# Raw colours that pre-date the token system — the phase-7 migration worklist.
#
# One entry per SOURCE LINE, not per occurrence: a single line can carry
# several (`'bg-black/45 text-white hover:bg-black/60'`). At the time this
# baseline was written that was 64 lines carrying
# 100 raw colours.
#
# Shrink this list; never add to it. Replacements:
#   border-white/N  -> border-surfaceGlass/N   (invisible in light mode today)
#   bg-white/N      -> bg-surfaceGlass/N
#   bg-black/N      -> bg-scrim/N              (modal scrims ONLY)
#   background: 'rgba(0,0,0,a)' -> 'rgb(var(--scrim) / a)'   (an inline-style scrim)
#   any black SHADOW      -> rgb(var(--shadow-color) / a)
#
# NOT bg-overlay/N, which an earlier version of this header prescribed for
# scrims: --overlay IS --bg-primary, and a translucent fill of the ground
# colour composites back to the ground colour at EVERY alpha, so a scrim
# built that way darkens nothing. --scrim is the token that exists for this.
#
# The shadow replacement was UNSAFE until 2026-08-16 and this header used to
# prescribe it anyway. `--shadow-color` was `10 20 19` — the dark page
# ground itself — handed to BOTH modes, so an ink shadow in dark mode had
# nothing left to darken: a 0.78-alpha drop shadow measured 1.7 units of
# separation from the page where black gave 12.0. `createBrand.ts` now
# defaults it PER MODE (black in dark, the brand ink in light), which makes
# the swap byte-identical in dark at every alpha and leaves light untouched.
# A shadow expresses a control ELEVATION, so it follows this token wherever
# the control sits — including over a photograph, where "darker" is right in
# both modes. Only TEXT-shadow on overlay text stays raw (class 1 below).
#
# ⚠️ NOT every entry should be migrated. Four classes below are PERMANENT
# residents — they are raw on purpose, and "fixing" them is the regression:
#
#   1. Anything painted on a PHOTOGRAPH, or on third-party imagery this app
#      does not restyle. A photo is dark in both modes, so its scrim,
#      caption chip and overlay text must be too. Includes
#      MediaFullscreenViewer, LookSlide, SheetCover, the media letterboxes
#      in MediaUploader / ImageEditModal / NewMediaPostForm, and the white
#      marker rings in search/MapView, which sit on OpenStreetMap's raster
#      tiles. Overlay TEXT on a photo keeps its raw text-shadow too: that
#      glow is tuned to the photograph, not to a surface that flips.
#      A subtree pinned `data-mode="dark"` counts here too — app/(main)/
#      looks/page.tsx pins the whole feed, so its raw blacks sit BESIDE
#      tokens already resolved to their dark values, not against them.
#   2. Anything rendered to an IMAGE rather than to the DOM. An exported PNG
#      carries no [data-mode]: lib/media/socialExportRender.ts composites on
#      a <canvas> and its colours are the artwork.
#   3. The BRAND MARK. lib/brand/brand.css keeps --on-cta and the --coin-*
#      stops constant across modes on purpose (the feather is drawn to read
#      on a dark disc); TovisFeatherMark and lib/brand/eyeSvg.ts are the same
#      artwork. Their drift is phase 8 of the register, not a colour swap.
#   4. The white SPECULAR sheen system — a `rgb(255 255 255/0.10–0.20)`
#      radial highlight layered under an accent/micro-accent gradient and a
#      `ring-white/8–10`, in admin ServiceHeroGrid, pro OfferingManager,
#      RouteOverlay and AddServiceOverlay. Its members only read together;
#      converting the ring without its own sheen, or either without the
#      gradient, half-migrates a coherent look. That is a design decision,
#      not cleanup — take the whole system or none of it.
#
# Classify by what the class lands on before touching it.
